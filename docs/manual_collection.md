> 生成于 2026-09-14，基于 `data/qa_corpus.json` **v1.6.0** 的真实内容（不是照抄旧文档）。
> 配套阅读：`docs/unsourced_intents.md`（风险分级）、`docs/pending_items.md`（待办）。
> 本清单回答三个问题：**问什么 / 为什么必须人工 / 要什么形式的答案**。

## 0. 一句话结论

语料 49 个意图里，**22 个没有可核来源**。其中 **12 个是 P0** —— 答案里写死了
金额、时刻、册数、比例这类"具体到数字"的断言，**我在沙箱里核不到**（学校没公开、
或属于内部制度），一旦与实际不符就是"明确答错"。这 12 个是本清单的主体。

**判断口径**：能靠"官网/公众号/文件"解决的，不算"必须人工"——那属于我再跑一次抓取。
下面标 🏃 的是**必须有人去现场或问到人**，标 🗄 的是**必须拿到内部制度/数据**，
标 ⚖️ 的是**不是查资料、而是口径决策**。

## 3. 需要"口径判断"而非"查资料"的问题（⚖️）

这三类**查不到也无所谓，但要你拍板**：

1. **顶层 `source` 死字段留还是删**：代码不读它，仅审计时可见；24 条里"后勤保障部""学生处心理咨询中心"
   等部门名不存在。删掉更干净、留着能看出作者原意。当前只修了 2 条。
2. **`campus_wifi` / `leave_apply` 的顶层 source 改写**：已在先前核实为"数智化处""学工处"，
   但要不要顺手把其余 22 条全过一遍，取决于你要不要把它当"审计材料"。
3. **12 个 P0 是"补齐原文"还是"降级为引导型"**：前者资料齐全时最理想，后者一条都不用等。
   建议：**能拿到原文的补原文，拿不到的先按引导型收口**（删掉具体数字），别留着无兜底断言。

## 5. 采完之后落到什么形式（三种 `_meta` 模板）

```jsonc
// A. 拿到官方通知原文（最理想）
"_meta": {"source":"教务处","category":"选课","url":"https://jwc.niit.edu.cn/...",
          "title":"关于 2026-2027 学年第一学期选课工作的通知","date":"2026-06-20",
          "type":"real_notice_v3","note":"摘录自通知第 2 条"}

// B. 拿到官方文档/网页（次优，v1.6.0 的 dorm_repair / psych_counseling 就是这么做的）
"_meta": {"source":"图书馆","category":"借阅规则","url":"https://lib.niit.edu.cn/...",
          "title":"图书馆借阅管理规定","date":null,"type":"official_doc","note":"..."}

// C. 拿不到原文 → 引导型（**删掉所有具体数字**，只留渠道）
"_meta": {"source":"学工处","category":"请假","url":null,"title":"请假流程（引导）",
          "date":null,"type":"guidance",
          "note":"未取得官方原文，仅写通用流程；取得后应替换为通知摘录型"}
```

**铁律**：宁可引导，不可编造。凡是写死数字又拿不出出处的，都属于"被追问一句就露底"。

## 6. 推进顺序建议

1. **先清 12 个 P0 里最像"内部数据"的 6 个**（library_borrow、library_seat、card_recharge、
   lost_card、medical、scholarship）—— 数字最硬、风险最大。拿不到原文就**先降级为引导型**（半小时能全改完）。
2. **再做 🏃 现场类**（校医院、事务大厅、图书馆、驿站、食堂、文印点）—— 跑一趟能一次清掉 8~10 条。
3. **最后补 P1/P2 的引导型**（它们本来就带"以…为准"，风险低，收益也低）。
4. 每改一条：更新 `meta.changelog` + 重跑 `python scripts/report_unsourced.py` 刷新清单。
