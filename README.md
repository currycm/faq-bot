## 它能做什么

### 一句话

把一个校园里**说得清、有标准答案**的问题，交给一个能 7×24 小时回答的机器人——
而不是让学生去翻十几个部门的网页，或者加群问「有没有人知道」。

它回答的方式分优先级，这个顺序很重要：

1. **知识库里有标准答案** → 直接给（绝大多数问题走这条路，不花钱、不联网、毫秒级）
2. **是天气这类实时信息** → 查真实天气接口，不让 AI 凭记忆瞎说
3. **是「我是谁」「你好」这类闲聊** → 给固定话术
4. **是它没收录的** → **如实说答不上来**，而不是硬编一个
5. 只有「什么是机器学习」这类通识问题，才会去问大模型

> **为什么这么设计？** 校园事务（选课、转专业、报销）涉及学生切身利益，
> 一旦 AI 编一个不存在的流程，学生照着做会白跑一趟。所以这类问题**宁可说不知道，也不让大模型自由发挥**。

### 它现在能回答哪些问题

覆盖 **87 类校务场景 / 675 条问法**，比如：

- 图书馆几点开门、一本书最多能借多久、怎么预约座位
- 宿舍几点关门、灯坏了找谁修、校园卡丢了怎么办
- 怎么退选一门课、怎么查成绩、怎么打印成绩单
- 奖学金怎么申请、怎么请病假、怎么预约心理咨询
- 今天/明天天气怎么样、什么是机器学习（这类通识问题交给大模型）

### 关键成果（可直接写进简历）

- **召回率从 52.0% 提到 99.6%**：把检索方案从「关键词匹配」换成「语义向量」（换成 BGE 中文模型）后，
  同一份测试集上召回@1 从 52.0% 涨到 99.6%，未识别率从 45.9% 降到 0%。
  **结论：与其堆同义词，不如换语义模型。**
- **四道安全防线**：自动识别并脱敏隐私信息、拦截「忽略之前的指令」这类越狱提问、
  限制刷接口频率、给大模型调用设成本上限。
- **184 个自动化测试**接进 GitHub Actions，并把**「召回率」也做成了 CI 门禁**——
  改动如果让效果变差，CI 会直接变红，不会悄悄退化。
- **做过抗并发优化**：加了答案缓存和慢路径隔离后，**同机实测** 全冷查询 173 请求/秒、
  热问法（缓存命中 94%）1866 请求/秒 —— 差 **10.8 倍**，慢请求导致的延迟劣化从
  **19 倍降到 1.3 倍**。数字都能用 `scripts/benchmark_throughput.py` 复现。
- **能一键部署**：Docker 多阶段构建 + Nginx 反代，模型只加载一次让多个进程共享。

### 这件事的非技术版总结

1. 从零搭了一套校园问答系统，覆盖 87 类场景、675 条问法，能答新生 90% 以上的常见问题
2. 设计了安全机制：自动屏蔽隐私信息、拦截恶意诱导提问、给大模型设置了花钱上限
3. 写了自动化测试和 CI 流程，包括「效果指标门禁」，保证改动不会把准确率做坏
4. 用数据驱动迭代：把答不上来的问题收集起来 → 补语料 → 复测指标
   并且给每条答案建了**来源台账**，能查到「这条答案出自哪个部门的哪份通知」
5. 做了交互式校园地图，新生一眼找到教学楼、食堂、宿舍

## 三分钟跑起来

> 这一节目标很明确：**让你在 3 分钟内看到它在自己机器上跑起来**。
> 只有 Python 和网络两个前提，不需要 Docker、不需要数据库。

### 第 0 步：确认环境

| 项 | 要求 | 说明 |
|---|---|---|
| Python | **3.11 或更高** | Docker 镜像用的是 3.11；本机实测 3.13 也可以 |
| 内存 | 建议 2GB 以上 | 中文语义模型占约 400MB |
| 网络 | 首次运行需要联网 | 要下载模型（约 93MB），之后就能离线跑 |
| 可选 | Docker / Redis | 想上生产再装，本地玩不需要 |

### 第 1 步：装依赖

```bash
git clone https://github.com/currycm/faq-bot.git
cd faq-bot

python -m venv .venv
source .venv/bin/activate          # Windows 用：.venv\Scripts\activate

pip install -r requirements.txt

# 注意：torch（模型计算库）故意没写进 requirements.txt
pip install torch --index-url https://download.pytorch.org/whl/cpu
```

> **为什么 torch 要单独装？** 因为默认源给的是带 NVIDIA 显卡支持的版本（1GB+），
> 而这个项目只用 CPU 跑，装 CPU 版就够了（小得多）。这一步是踩过坑才写下来的。

### 第 2 步：配置密钥（可选）

**什么都不配也能跑**——知识库问答完全离线可用，只是「今天天气」「什么是机器学习」这类会降级成固定话术。

想用完整功能，配一个 DeepSeek 密钥就够：

```bash
# 方式一（推荐）：环境变量
export DEEPSEEK_API_KEY=sk-xxx        # Windows PowerShell: $env:DEEPSEEK_API_KEY="sk-xxx"
export HEFENG_API_KEY=xxx             # 天气功能，可选

# 方式二：写进 .env 文件（这个文件已在 .gitignore 里，不会被提交）
cp .env.example .env
# 然后用编辑器打开 .env 填进去
```

> ⚠️ **最容易踩的坑**：`.env` 是**程序启动那一刻读一次**的。
> 改完必须**重启程序**才生效——否则会表现为「配置明明改了，行为就是不变」，
> 很容易误判成代码有 bug（这个坑我踩过，排查了很久）。

密钥的读取优先级：`环境变量` → `secrets/xxx_key.txt`（Docker 密钥文件）→ 空。

### 第 3 步：启动

<details>
<summary><b>方式 A：网页版（推荐先试这个）</b></summary>

```bash
streamlit run app.py
```

浏览器打开提示的地址（默认 <http://localhost:8501>）就能看到聊天界面。
</details>

<details>
<summary><b>方式 B：后端 API + 前端分离</b></summary>

```bash
# 终端 1：起后端（端口 8000）
uvicorn api:app --host 127.0.0.1 --port 8000

# 终端 2：起前端，并告诉它后端在哪
export FAQ_API_BASE=http://127.0.0.1:8000
streamlit run app.py
```

> 不设 `FAQ_API_BASE` 时，前端会**直接在自己的进程里调用机器人**，不用起后端——
> 这种单进程模式适合部署到免费空间（内存小）。
</details>

<details>
<summary><b>方式 C：纯命令行（不联网、不装网页依赖）</b></summary>

```bash
python -m src.agent
```

进去以后可以用的命令：

| 命令 | 作用 |
|---|---|
| `/help` | 帮助 |
| `/stats` | 看当前状态（语料条数、向量化方式） |
| `/reload` | 改了语料后热更新，不用重启 |
| `/top` | 看上一个问题召回了哪 3 条候选 |
| `/exit` | 退出 |
</details>

### 第 4 步：验证装对了

```bash
python -m pytest -q                   # 184 个测试
python evaluate.py                    # 跑效果评估，应看到召回率 99.6%
curl http://127.0.0.1:8000/health     # 后端健康检查
```

> 没起后端时，有 7 个前端集成测试会显示 `skipped`。**skipped 不等于通过**——
> 想跑全 184 个，先按方式 B 把后端起起来。

## 不懂 NLP 也能看懂：名词速查

> 这一节给不熟悉本领域的人。**跳过它不影响你跑起来**，但看后面的架构说明会顺很多。

| 名词 | 大白话解释 |
|---|---|
| **RAG**（检索增强生成） | 先"查资料"再"回答"的思路。机器人不是凭记忆答，而是先从你准备好的知识库里找出最相关的一条，再据此回答。好处是答案可追溯、不会凭空编。 |
| **向量 /  embedding** | 把一句话变成一串数字（比如 512 个小数）。**语义相近的句子，数字也相近**，于是"像不像"就变成了"算距离"。 |
| **BGE** | 一个中文语义模型的名字（这里是 `bge-small-zh-v1.5`，约 93MB）。它的活儿就是把句子转成上面说的那串数字。 |
| **余弦相似度** | 衡量两串数字"方向有多接近"，取值 0~1，越接近 1 越像。**本项目的判定线是 0.60**：算出来 ≥ 0.60 就认为命中了知识库。 |
| **召回率@1（召回@1）** | 评测指标：给 100 个问题，**排在第一位的答案就对**的比例。99.6% 意味着 100 题里约 99 题一次就对。 |
| **Top-3 命中率** | 放宽一点：正确答案排在**前三位**就算对。本项目是 100%（排第一就对了，所以前三必然对）。 |
| **误答率 / 未识别率** | 误答 = 不该答却答了；未识别 = 该答却答不上来。两个都要低。 |
| **精排（rerank）** | 检索出候选后，再用一个更慢更准的模型重新排序。本项目**代码写好了但实测后仍默认关闭**——`bge-reranker-base` 在这套语料上是净负的（召回@1 99.6%→92.9%，延迟 ×13.2），原因与适用场景见 [`docs/rerank_report.md`](docs/rerank_report.md)。 |
| **TF-IDF** | 更老的关键词匹配方案。只认字面重叠："寝室灯泡坏了"和"宿舍灯坏了"它认为**毫不相关**（因为没有相同的词），所以效果差很多。项目保留了它作为对比和入门选项。 |
| **令牌桶限流** | 限速器：给每个 IP/用户发一个"桶"，里面有一定数量的"令牌"，每次请求消耗一个，令牌按固定速度补充。桶空了就拒绝请求。 |
| **熔断 / 预算熔断** | 保险丝：如果大模型调用次数或花费超过设定的上限，就自动切断这条通路，改用固定话术兜底，避免账单失控。 |
| **COW（写时复制）** | 操作系统的小聪明：多个进程共享同一块内存，只有真的改写时才复制一份。本项目用它让多个服务进程**共用一份模型**，而不是各存一份。 |
| **NAT（网络地址转换）** | 校园网里几百人常常共用一个对外 IP。所以"按 IP 限流"在这类网络下会**误伤**——这是本项目一个已知问题，见[常见问题](#常见问题)。 |

## 它是怎么工作的

> **一句话**：把你的问题和知识库里 675 条问法都变成"语义向量"，算出最像的那条，够像就返回它的答案；
> 不够像就走兜底分流。相似度低于阈值时**宁可说不知道，也不乱答**。

![系统架构图](docs/architecture.svg)

### 一次提问的完整旅程

```
学生提问：「宿舍灯坏了找谁修」
  │
  ├─ 第 1 关：安全检查（有没有夹带隐私信息 / 是不是恶意诱导提问）
  │           命中高风险 → 直接拒绝，不进入后续任何环节
  │
  ├─ 第 2 关：限流（这个人 / 这个 IP 是不是问得太频繁了）
  │
  ├─ 第 3 关：查答案缓存（这问题刚有人问过吗？）
  │           ★ 必须放在安全检查之后 —— 否则缓存会让限流形同虚设
  │
  ├─ 第 4 关：知识库检索
  │     ├─ 找到（相似度 ≥ 0.60）→ 直接返回答案 ✅ 完事，不花钱、不联网
  │     └─ 没找到 ↓
  │
  ├─ 第 5 关：慢路径闸门（这类兜底要 1.4~8 秒，不能让它们把"快通道"堵死）
  │           闸位满了 → 立刻返回「暂时答不上」，不排队
  │
  ├─ 第 6 关：兜底分流
  │     ├─ 闲聊（你好 / 谢谢）→ 固定话术
  │     ├─ 实时（天气）→ 真实天气接口
  │     ├─ 校园事务  → 固定话术（**绝不交给大模型编造**）
  │     └─ 通识（什么是…）→ 大模型
  │
  └─ 第 7 关：预算熔断（1 小时内大模型调用不超 500 次 / 估算 10 元）
             超了 → 降级成固定话术，其它通道照常工作
```

### 两套检索方案

| 方案 | 模型大小 | 单句耗时 | 中文语义匹配 | 用在哪 |
|------|---------|---------|-------------|--------|
| TF-IDF | 无 | <1ms | ❌ 只认字面重叠 | 学习流程、离线演示、极端省资源场景 |
| **BGE（默认）** | ~93MB | 5-15ms（索引后查询 0.5ms） | ✅ 强 | 真实使用 |

### 为什么它能扛住并发

这不是天生的，是 2026-09 专门优化过一轮的结果：

| 做了什么 | 解决什么问题 | 效果（同机实测） |
|---|---|---|
| **加答案缓存** | 同一个问题被反复问，却每次都要重算一遍语义向量 | 吞吐 **173 → 1866 请求/秒**（并发 32，全冷查询 vs 缓存命中 94%） |
| **隔离慢路径** | 「查天气/问大模型」要 1~8 秒，和 10 毫秒的知识库检索**共用线程池**，慢请求一多就把快请求全堵住 | 延迟劣化 **19 倍 → 1.3 倍** |
| **限制模型计算线程数** | 每个计算任务都想吃满所有 CPU 核，和并发请求叠加后互相抢资源 | 高并发下吞吐 **+20%** |
| **`gunicorn --preload`** | 每个服务进程都自己加载一份模型（每份约 400MB） | 多进程**共用一份**模型内存 |
| **冷逻辑移出热路径** | 每写一条日志都做一次 `mkdir` 系统调用（实测 0.37 ms/次），而目录启动后就一直存在；`ask()` 里的空输入/安全拒答/缓存命中三个冷分支也抽成了独立函数 | 单请求端到端 **−3.9%**，**缓存命中路径 −44.6%** |

## 功能清单

| 功能 | 说人话 | 相关代码 |
|---|---|---|
| **语义检索问答** | 问题与 675 条问法比相似度，够像就直接回答（**不消耗大模型额度**） | `src/retriever.py` |
| **兜底分流** | 答不上来的问题按性质分流，校园事务绝不让大模型编 | `src/fallback/router.py` |
| **安全层** | 隐私脱敏 + 越狱拦截 + 限流 + 成本熔断，四道关卡 | `src/security/` |
| **答案缓存** | 同样的问题不用算第二遍；但**位置在安全层之后**，不绕过限流 | `src/cache.py` |
| **慢路径隔离** | 给耗时的兜底链路设并发上限，保护毫秒级的检索通道 | `src/agent.py` |
| **校园地图** | 双校区手绘地图，支持缩放拖拽，零外部依赖（离线也能看） | `src/campus_map.py` |
| **答案溯源** | 每条答案标注来源类型（通知原文 / 官方文档 / 引导型），可审计 | `docs/` 下各文档 |
| **日志与采集** | 记录问答日志，并把"答不上来"的问题单独收集，供后续补语料；写日志的目录创建已移出热路径 | `src/logger.py` |
| **界面去 AI 味** | 高频问题常驻可点，来源显示成一行灰字，调试信息默认隐藏 | `app.py` / `src/ui_style.py` |

## 使用示例

### 用 HTTP 接口调用

```bash
curl -X POST http://127.0.0.1:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"query":"图书馆几点开门","user_id":"u-001"}'
```

答案在知识库里时，返回长这样：

```json
{
  "answer": "图书馆周一至周日 8:00-22:00 开放…",
  "matched": true,
  "tag": "library_hours",
  "score": 1.0,
  "cache_hit": false,
  "trace_id": "...",
  "vectorizer": "bge",
  "security": {"reason": "", "pii_hits": [], "injection_rules": []}
}
```

没答上来时，`matched` 是 `false`，`fallback` 会告诉你它走了哪条通道：

```json
{"matched": false, "fallback": {"type": "weather", "source": "weather", "rule": "realtime_weather"}}
```

接口一共三个：`/ask`（问答）、`/suggest`（首页那 7 个高频问题）、`/health`（健康检查）。

### 用 Python 直接调用（不用起服务）

```python
from src.agent import FaqBot

bot = FaqBot()  # 默认用 BGE；想对比可传 vectorizer_type="tfidf"
r = bot.ask("宿舍灯坏了找谁修", user_id="demo")
print(r["matched"], r["tag"], r["answer"])

bot.reload()  # 改了语料后热更新（会顺带清空答案缓存）
```

### 用 Docker 部署

```bash
# 1. 准备密钥文件（注意 -n 不要换行）
echo -n "sk-xxx"   > secrets/deepseek_key.txt
echo -n "your-key" > secrets/hefeng_key.txt

# 2. 构建（首次约 10 分钟，主要花在 torch 196MB + BGE 模型 93MB 的下载上）
docker build -t faq-bot:v8 .

# 3. 启动
docker compose up -d

# 4. 验证
curl http://127.0.0.1:8000/health
```

镜像约 2.4GB，启动后约 20 秒完成模型加载（健康检查给了 60 秒宽限）。

## 实测效果

> **先说清楚测试怎么做的**：测试集 242 条（239 条可答 + 3 条应拒答），
> 是**人工改写**出来的，和语料里的原句**不重复**——换同义词、改语序、加口语助词。
> 这一点很关键：拿语料原句当测试集，等于考卷上就是答案，测出 100% 没有意义。

两套方案对比：

| 方案 | 构建耗时 | 召回@1 | Top-3 命中 | 未识别率 | 误答率 | 命中延迟 P50 |
|------|---------|--------|-----------|---------|-------|---------|
| TF-IDF | 36 ms | 52.0% | 93.3% | 44.4% | 3.6% | 1.3 ms |
| **BGE（默认）** | 10.0 s（含模型加载） | **99.6%** | **100%** | **0.0%** | **0.4%** | 10.9 ms |

当前各项指标：

| 指标 | 实测 | 目标 | 达标 |
|------|------|------|------|
| 召回率@1 | 99.6% | ≥ 80% | ✅ |
| Top-3 命中率 | 100.0% | ≥ 95% | ✅ |
| 未识别率 | 0.0% | ≤ 10% | ✅ |
| 误答率 | 0.4% | ≤ 5% | ✅ |
| **误触发率** | **0.0%** | ≤ 10% | ✅ |
| 整体准确率 | 99.6% | — | — |

### 三个必须说清楚的点

**1. 99.6% 是「封闭测试集」的成绩，别当真实水平。**
语料和测试集都是我一个人写的，真实用户问法要发散得多，上线后准确率**一定会降**。
所以真正的办法不是死磕算法，而是靠运营闭环——定期把 `logs/unmatched.jsonl` 里
「没答上来」的问题捞出来，补进语料。

**2.「误触发率 0%」是真的降下来了，但分母还是太小。**
原来 25%（4 条应拒答里错 1 条）。那 1 条是「学校附近哪家火锅好吃」被 `canteen_info`
以余弦 0.6563 抢走，答成了校内食堂营业时间——**语义像，但答非所问**。
修法不是调阈值（会连累召回），而是**新增一条 `off_campus_info` 边界意图**：
明说「校外餐饮购物我查不到，我只覆盖校内」，再给两个校内问题做引导。
这样既不再答非所问，也把服务边界对学生讲清楚了。
不过应拒答样本现在只剩 3 条，**一条就占 33%，统计上仍然没意义**，扩样本仍在待办里。

**3. 精排（更准的二次排序）代码写通了，但默认关闭。**
因为它在这里没用武之地：BGE 在封闭测试集上已经 99.6% 命中，排第一就对了，再排一次不会更好。
它的价值要在**更容易混淆的问题**上才体现得出来，那需要更大的评测集才能验证。

> 复现命令：`python scripts/benchmark_retrieval.py`（三方案对比）、`python evaluate.py`（当前指标）。
> 想开精排：`src/config.py` 里设 `ENABLE_RERANK=True`（模型 `BAAI/bge-reranker-base`，
> 首次启用会联网下载；启用后命中判定走 `RERANK_THRESHOLD`，**0.5 只是占位值，要重新标定**）。

## 配置说明

### 环境变量

| 变量 | 默认 | 作用 |
|---|---|---|
| `DEEPSEEK_API_KEY` | （空） | 大模型密钥。不配则通识问题降级为固定话术 |
| `HEFENG_API_KEY` | （空） | 天气接口密钥。不配则天气问题降级 |
| `HF_HOME` | 系统默认 | 模型缓存位置（国内可指向已有的缓存目录，省一次下载） |
| `FAQ_REDIS_URL` | （空） | 填了就改用 Redis 统一计数（多进程时限额才准确） |
| `FAQ_TRUST_PROXY_HEADERS` | `0` | 是否信任代理传来的客户端 IP。**只有 API 藏在可信反向代理后面时才开**；直连部署必须关，否则限流可以被伪造请求头绕过 |
| `FAQ_CORS_ORIGINS` | 本地地址 | 允许跨域访问的来源 |
| `FAQ_DEBUG` | `0` | 前端调试模式：显示追踪 ID、相似度、候选列表 |
| `FAQ_API_BASE` | （空） | 前端要连的后端地址；不填则前端自己进程内直接调用 |
| `FAQ_ANSWER_CACHE` | `1` | 答案缓存开关 |
| `FAQ_SLOW_PATH_MAX` | `8` | 兜底链路的最大并发数（超了就立刻降级） |
| `FAQ_TORCH_THREADS` | `1` | 模型计算的线程数（CPU 场景靠多进程提速，不靠进程内多线程） |

### 安全与额度参数（`src/config.py`）

| 变量 | 默认 | 作用 |
|---|---|---|
| `SECURITY_ENABLED` | True | 安全层总开关（生产环境必须开着） |
| `REDACTION_ENABLED` | True | 隐私信息脱敏 |
| `INJECTION_ENABLED` | True | 越狱提问检测 |
| `RATE_LIMIT_IP_CAPACITY` / `_REFILL` | 30 / 0.5 | 每个 IP：最多攒 30 次，每秒回补 0.5 次 |
| `RATE_LIMIT_USER_CAPACITY` / `_REFILL` | 60 / 1.0 | 每个用户：最多攒 60 次，每秒回补 1 次 |
| `BUDGET_WINDOW_SEC` / `_MAX_CALLS` / `_MAX_COST_CNY` | 3600 / 500 / 10.0 | 1 小时内最多调 500 次大模型、估算花费不超 10 元 |
| `DEEPSEEK_TIMEOUT` | 8 秒 | 超时直接降级 |
| `HEFENG_TIMEOUT` | 6 秒 | 同上 |

> ⚠️ **限额的精度问题**：没配 Redis 时，限流和预算是**每个进程各算各的**，
> 所以多进程部署时实际额度 ≈ 进程数 × 配置值。
> 想要精确限额就配 `FAQ_REDIS_URL`（`docker-compose.yml` 里有注释好的 redis 服务）。
> Redis 连不上会自动退回进程内计数，**不会因此拒绝服务**。

### 它能防住什么

| 你担心的 | 它怎么防 |
|---|---|
| 大模型编造校务流程 | 系统提示词钉死边界 + 校园关键词拦截在大模型之前 |
| 大模型编造天气 | 天气永远查真实接口，不进大模型 |
| 账单失控 | 超时降级 + 1 小时调用次数/花费上限 |
| 密钥泄露 | `.env` 不进仓库；写日志前强制脱敏 |
| 大模型接口异常 | 任何异常都降级成固定话术，不会抛 500 |
| 用户在提问里贴了手机号 | 自动脱敏成 `[手机号]`，原文只在返回给用户时保留 |
| 「忽略之前的指令」这类攻击 | 检测到高风险直接拒答 |
| 有人刷接口 | 令牌桶限流 |
| 月底被刷爆账单 | 滑动窗口成本熔断 |

## 常见问题

<details>
<summary><b>Q1. 为什么写 99.6% 而不是 100%？是不是变差了？</b></summary>

不是变差，是**测试集变难了**。

早期版本确实到过 100%，但那是在 97 条测试集上。后来把测试集扩到 242 条
（新增更多口语化、省略式问法）后，暴露出 1 条真实未命中，所以是 99.6%（238/239）。

**指标数字必须跟着测试集一起说**，否则就是自欺欺人——这也是我特意把测试集规模写在结论旁边的原因。
</details>

<details>
<summary><b>Q2. 语料里怎么会有一条「校外周边」这种不是校方政策的意图？</b></summary>

**因为它是「服务边界」，不是「知识」。**

之前「学校附近哪家火锅好吃」会被 `canteen_info`（校内食堂）以余弦 0.6563 抢走，
答成食堂营业时间——学生问校外、机器人答校内，属于**答非所问**。
这类问题的正确做法不是拒答，而是**明确告诉用户边界在哪**，所以加了 `off_campus_info`：

> 校外的餐饮、购物、娱乐我这边查不到 —— 我只覆盖校内场景（食堂、宿舍、图书馆、选课、校园卡）。
> 校内的可以问我，比如「学校有几个食堂」。

它在溯源台账里标为 `guidance` 型：`url` / `date` 都是空的，
`note` 里写清了「这是刻意的产品边界，不是校方政策」——**不冒充官方来源**。
代价是应拒答样本从 4 条降到 3 条（这条现在算「该给边界说明」而非「该拒答」），
所以误触发率归零有一部分是口径变化，这点在「实测效果」里也写明了。
</details>

<details>
<summary><b>Q3. 为什么不做模型训练 / 微调？</b></summary>

因为**这个场景不需要**。

语料是封闭的 FAQ（87 个意图），用现成的中文语义模型做检索就能拿到 99%+ 的召回。
训练模型要标注数据、要算力、要调参，收益还不如「把每条问法补到 8 条覆盖不同说法」。

> **这条论断做过实测了**（`docs/holdout_eval_report.md`）：每意图从 8 条砍到 3 条，召回@1 从 96.7% 掉到 **76.5%**（−20.2 个百分点），而且**下降近似线性、看不到饱和点**。
> 即**索引覆盖度是召回的主要杠杆**，方向确实比换算法更值钱。

工程上先问一句「这个问题必须用训练模型解决吗」——答案是否的时候，**不做才是最对的选择**。
顺便说明：本项目**没有训练环节**，用的是预训练模型，面试时别被问住 😉
</details>

<details>
<summary><b>Q4. 模型下载不动 / torch 装不上</b></summary>

```bash
# 用国内镜像加速模型下载
export HF_ENDPOINT=https://hf-mirror.com
export HF_HOME=/path/to/your/hf_cache      # 已经有缓存的话直接指过去

# torch 一定要装 CPU 版，否则会拉 1GB+ 的显卡支持包
pip install torch --index-url https://download.pytorch.org/whl/cpu
```

网络实在不行也别慌：`src/config.py` 里把 `VECTORIZER_TYPE` 改成 `tfidf`
就能**零模型依赖**跑起来（代价是召回率从 99.6% 掉到 52.0%）。
</details>

<details>
<summary><b>Q5. 改了语料 / 配置为什么不生效？</b></summary>

两个最常见的原因，按概率排序：

**① 改了 `.env` 或环境变量，但没重启程序。** 这些是**启动那一刻读一次**的，
改完必须重启。症状是「配置明明对了，行为就是不变」——很容易误以为是代码问题。

**② 改了语料但没热更新。** 命令行里输入 `/reload`，或代码里调 `bot.reload()`，重启也可以。
注意 `reload()` 会**同时清空答案缓存**（这是故意的，否则会返回上一版语料的答案）。

另外：`src/ui_style.py` 的样式和 `.streamlit/config.toml` 的主题都是启动时读的，改完也要重启。
</details>

<details>
<summary><b>Q6. 前端说「服务暂时不可用」，怎么查？</b></summary>

按这个顺序排查，一般三步内能定位：

1. **后端起了吗？** `curl http://127.0.0.1:8000/health` 应该返回 `{"status":"ok","ready":true}`
2. **前端指向对吗？** 设了 `FAQ_API_BASE` 就按它走；不设的话前端应该在自己进程内调用，不需要后端
3. **端口被旧进程占着吗？** 换个端口起一个对比一下
4. 如果 `ready` 是 `false`，说明模型还在加载（首次约 6~20 秒），等一会儿就好
</details>

<details>
<summary><b>Q7. 限流会不会误伤正常用户？</b></summary>

**会，这是已知问题。** 规则是每个 IP 最多攒 30 次、每秒回补 0.5 次，
而**校园网普遍是 NAT**——一栋宿舍楼可能几百人共用一个对外 IP，那就等于几百人抢 30 个名额。

多进程部署会宽松些（每个进程各有一份计数），但那只是掩盖问题。
正确做法是：IP 限制只当「防刷上限」（容量设大），真正的业务限流看用户 ID。已列入待办。
</details>

<details>
<summary><b>Q8. 日志文件会越来越大吗？</b></summary>

会。目前是**追加写、没有轮转**。`logs/` 已经在 `.gitignore` 里，所以不会污染仓库，
但磁盘会涨，排查问题时要手动翻。规模上来后应该加按天切分或异步写入。

当前规模可以接受，**但建议知道这个边界在哪**。
</details>

<details>
<summary><b>Q9. 为什么要给大模型设「预算熔断」？</b></summary>

因为**没有上限的调用 = 没有上限的账单**。

设计上有三层保护：
- 命中知识库的问答**完全不消耗**大模型额度（绝大多数请求都是这类）
- 只有通识类问题才调大模型，且 1 小时内不超过 500 次 / 估算 10 元
- 额度用完后**只影响通识通道**，闲聊、天气、校园事务照常工作

第 3 点是踩坑改出来的：早期版本在分流之前就检查预算，结果预算一耗尽，
连「你好」都被拒答，等于全站瘫痪。
</details>

<details>
<summary><b>Q10. 语料里的答案怎么保证不是编的？</b></summary>

建立了**来源台账**，每条答案在 `_meta` 字段里标明来源类型：

| 类型 | 含义 |
|---|---|
| `real_notice_v3` | 摘录自学校部门的**通知原文**（带链接、标题、日期） |
| `official_doc` | 取自官方**文档 / 网页** |
| `manual_verified` | **人工核实**：问询 / 现场确认得来，有核实对象和日期，但**没有原文链接可引** |
| `guidance` | **流程引导型**：没有原文可摘，只写通用办理流程 + 官方渠道，**不写校方具体数字** |

目前 87 个意图里，24 条有官方原文、34 条取自官方文档、**20 条为人工核实**、8 条为流程引导型，
只剩 1 条（`campus_map_guide`，纯界面说明）不需要外部溯源。

**人工核实这 20 条是怎么来的**：`docs/manual_collection.md` 原本是一份可执行清单，
逐条写清楚「要搜集什么 / 为什么必须人工 / 期望的答案形式」，回收后的数据
在 v1.8.0 统一回填，此后逐年补充。它的可信度**高于作者推测、低于有原文可引**，
而且没有 url —— 所以凡涉及时间、金额、地点、数量的数字，每学年要复核一次。

**原则是：宁可写引导，也不编造。**
接手这个项目的同学，建议先读 `docs/pending_items.md`。
</details>

## 已知限制

这一节是**主动交代短板**——知道边界在哪，比假装没有边界更有用。

| 限制 | 说明 | 影响 |
|---|---|---|
| **限流按进程计数** | 没配 Redis 时，多进程额度 ≈ 进程数 × 配置值（实测 80 并发放行 52 次 ≈ 2×30） | 配额不准；配 `FAQ_REDIS_URL` 可解 |
| **校园 NAT 下 IP 限流偏紧** | 几百人共用一个 IP，抢 30 个名额 | 可能误伤，见 Q7 |
| **误触发率 0% 但无统计意义** | 应拒答样本只剩 3 条，一条就占 33% | 指标仍失真，需扩到几十条 |
| **没有真实用户数据，结论都建立在自建封闭集上** | 语料与测试集出自同一作者，用词习惯一致；本想用线上未命中日志当开放集，核实后发现它去重仅 210 条、其中 **132 条直接来自测试集**（其余是压测循环）→ 不能当开放集 | 所有指标**只能声称相对趋势**，绝对数字偏乐观；已用**留出集**做诚实替代（`docs/holdout_eval_report.md`） |
| **测试集已被自己的问法分布封顶** | 索引覆盖了它的问法分布，所以「继续扩语料」不会让它涨。扩语料的真实收益在**尚未被想到的长尾问法**上，而那部分现有测试集**测不到** | 别用这个数字宣称"还能更高" |
| **召回 99.6% 里那 1 条是测试设计问题** | 测试句「去学校要准备什么证件和材料」自身有歧义（未说明是新生报到还是补办证件），被 `jwc_student_id_reissue` 的问法「补办学生证需要什么材料」以 0.8022 抢走，正解 `enrollment_report` 为 0.7916 | **刻意不修**：它是真实失败模式，删掉等于抹掉证据；已在 `tests/test_set.json` 该条上标注 note |
| **天气只支持今天/明天/后天** | 更远的日期（「周末」「下周」）会回落到实况 | 功能边界 |
| **精排实测后是净负的** | 召回@1 **99.6% → 92.9%**（K=3），排序层延迟 **11.8ms → 156ms（13.2×）**；204 条基线里只有 1 条"可救"，精排却改动了 33 条排序、弄坏 14 条（该组细分数字取自 `docs/rerank_report.md` 的 204 条基线）。成因是**句式压过话题**（详见报告） | **默认关闭是正确设置**；适用场景与改进方向见 `docs/rerank_report.md` |
| **前端不适合多人并发** | Streamlit 单进程 + 每次交互重跑整个脚本 | 多人同时用，前端会先于后端成为瓶颈 |
| **镜像偏大（2.4GB）** | 含 CPU 版 torch + 模型 | 首次拉取慢 |
| **20 个意图为「人工核实」** | 有核实对象与日期，但**没有原文可引**，会随政策过期 | 每学年复核一次涉及时间/金额/地点/数量的数字 |
| **官网口径比实际旧** | 图书馆官网《借书规则》《常见问题》都写「学生 30 册 / 60 天」，2026-09-15 电话向流通部核实，实际是「本科 10 册 / 30 天、研究生 15 册 / 60 天」——**语料是对的** | 提示：**有 url 不等于内容正确**；本条反而不能用官网做溯源 |

## 想深入：开发与运维

### 测试与 CI

```bash
python -m pytest -q --cov=src --cov-fail-under=80   # 184 个用例 + 覆盖率门禁
ruff check . && ruff format --check .               # 代码规范 + 格式（版本须与 CI 一致，见下）
python evaluate.py --min-recall 0.98                # 效果门禁（CI 跑的就是这条）
```

CI（`.github/workflows/ci.yml`）在 `ubuntu-latest` 上依次做五件事：
**代码规范与格式检查 → 启动 API 服务 → 跑测试（含覆盖率门禁）→ 跑效果门禁**。

倒数据前先说清楚三道门禁各挡什么：

| 门禁 | 命令 | 挡什么 |
|---|---|---|
| 格式 / 规范 | `ruff check .` + `ruff format --check .` | 风格漂移。**ruff 版本在 CI 里被钉死**（`ruff==0.16.8`）——不钉死的话上游一发版，CI 就会因为格式化风格变化而无辜变红 |
| 覆盖率 | `pytest --cov-fail-under=80` | 改动把测试覆盖率拖到 80% 以下（当前 81.1%，**余量只有 1 个点，别在没测到的分支上继续加代码**） |
| 效果 | `evaluate.py --min-recall 0.98` | 召回率低于 98%。**单元测试只能保证「代码没坏」，保证不了「效果没掉」** |

最后一条是关键：改了检索逻辑或语料后，召回率可能悄悄下滑而测试全绿——所以把召回率也做成了
可以自动判定的出口（低于基线就退出码非零，CI 变红）。

> CI 已经用 `actions/cache` 缓存了模型文件，不用每次重新下载 93MB。

### 怎么加新的问答

编辑 `data/qa_corpus.json`，往 `intents` 数组里加一条：

```json
{
  "tag": "print_service",
  "questions": ["哪里可以打印东西", "打印店在哪", "怎么打印文件", "学校打印贵不贵", "自助打印在哪里"],
  "answer": "打印店位于学生服务中心 2 楼，黑白 0.2 元/页，彩色 1 元/页。",
  "_meta": {
    "source": "学生服务中心", "category": "生活服务",
    "url": "...", "title": "...", "date": "2026-09-01", "type": "official_doc"
  }
}
```

三条经验：

1. **`questions` 至少写 5 条**，覆盖口语、书面、省略、倒装等不同说法。
   **这一条对准确率的贡献比换更强的算法还大。**
2. 改完在命令行输入 `/reload` 就能生效，不用重启。
3. 专业名词被分词工具切碎时（比如「勤工助学」被切成「勤工/助学」），
   把它加进 `src/config.py` 的 `CUSTOM_WORDS`。
4. **能给 `_meta` 就给**：它是「这条答案有出处」的凭据，也是后续审计和核对的依据。

### Docker 部署踩过的 4 个坑（2026-09-08 实测）

| # | 现象 | 根因 | 怎么解决 |
|---|---|---|---|
| 1 | 明明装了 CPU 版 torch，装依赖时又去下载 1GB 的显卡版 | 用 `--prefix` 安装的包不在 Python 的搜索路径上，pip 以为没装，从主源重新找（主源只有显卡版） | 设置 `ENV PYTHONPATH=/install/lib/python3.11/site-packages`，让 pip 看见已装的 CPU 版 |
| 2 | `ResolutionImpossible` 依赖无解 | 试过用约束文件钉死 `torch==2.14.0+cpu`，但主源里根本没有这种带 `+cpu` 的版本 | 放弃约束方案，改用上面的 PYTHONPATH 办法 |
| 3 | `RUN python -c "..."` 多行书写报 `IndentationError` | Dockerfile 会保留行首空格 | 写成单行，或复制一个 `.py` 文件进去执行 |
| 4 | 容器里密钥文件挂载正常，却一直提示「KEY 未配置」 | `config.py` 里 `_load_secret` 有**两处**定义，后面那个把支持密钥文件的版本覆盖掉了 | 只保留一处定义（`tests/test_secret_loading.py` 有防回归断言） |

### 和风天气的 Host 配置（最容易搞错的一处）

- 自定义域名前缀是**控制台分配**的（形如 `mc3byj5bbc`），**不是** API Key 的前 8 位。
  填错时返回的是「`Content-Length: 0` 的裸 403」，**不是**标准的错误 JSON，
  特别容易误判成网络故障。判断办法：**不带 Key 直接请求**，如果也是裸 403，就是域名填错了。
- 自定义域名下，天气查询和城市查询**共用同一个域名**，只有路径不同：
  - 天气 → `{BASE_URL}/v7/weather/now`
  - 城市 → `{BASE_URL}/geo/v2/city/lookup`

  代码里城市查询拼的是 `{HEFENG_GEO_URL}/v2/city/lookup`，所以 `HEFENG_GEO_URL`
  **必须写成 `...re.qweatherapi.com/geo`（带 `/geo`）**。
  只有用官方 devapi 账号才写 `https://geoapi.qweather.com`。

### 前端：怎么去掉「AI 味」

**核心判断：AI 味不是配色问题，是「开发者关心的信息」和「用户关心的信息」混在一起了。**

原来一条回答叠了 5 层：emoji 标题 + 技术栈副标题 + 橙色警示色块 + 彩色徽章 + 追踪 ID 详情。
其中至少 3 层学生根本不看。砍掉调试信息、改掉文案，就能消掉大约 70% 的 AI 味——
**比换配色有效得多**。

| 位置 | 改前 | 改后 |
|---|---|---|
| 标题 | 🎓 校园 FAQ 问答助手 + "v7 (FastAPI 后端)" | 校园问答 + 学校名 |
| 来源 | 5 色徽章 + 匹配度 87% | 一行灰字「来自知识库」 |
| AI 回答 | 橙色警示色块 + 徽章，说了两遍 | 只留一行「AI 生成 · 非官方答复」 |
| 候选 | 3 条进度条 + 分数 `0.872` | 未命中时才出现的「你可能还想问」可点按钮 |
| 加载/反馈 | 「正在思考…」「已收到反馈，我们会改进」 | 「查询中」+ toast「谢谢」 |
| 侧边栏 | 常驻「运行状态 / 反馈统计」两个面板 | 整块删掉；反馈统计挪到页面底部，只在调试模式显示 |
| 高频问题 | 只在首屏出现一次，问完就被顶走 | 常驻输入栏上方，7 个可点的 chip |

### 调试模式

排查问题时，在启动前端的终端里设 `FAQ_DEBUG=1`，才会显示
追踪 ID、相似度、候选题列表、向量化方式、API 地址。**默认一律不显示。**

> 2026-09 修复：调试开关从网址参数 `?debug=1` 改成了环境变量。
> 因为网址参数**任何访客都能加**，等于无鉴权泄露内部信息（`tests/test_ui.py` 有断言钉死这点）。

### 主题与样式

- 主题配置：`.streamlit/config.toml`（改完**必须重启**，不支持热更新）
- 样式覆盖：`src/ui_style.py`（去掉顶部彩虹条、页脚、彩色气泡、过重描边）

> ⚠️ **主色写在两个地方，改色时必须同步！**
> `config.toml` 的 `primaryColor` 管 Streamlit 原生组件，`src/ui_style.py` 的 `PRIMARY` 管自定义样式。
> `config.toml` 读不到 Python 变量，只能手工保持一致。

样式代码放在 `src/` 而不是项目根目录，是因为 Dockerfile 只复制
`api.py / app.py / src/ / data/` 这几项——在根目录新建 `.py` 不会进镜像，容器里 import 会报错。

### 三个必踩的坑（已经替你趟过）

1. **索引和查询必须用同一套预处理。**
   早期版本索引用原始句子、查询用分词后的句子，两边词汇表对不上，
   相似度恒为 0 **而且不报错**。现在预处理已经内聚到 `Retriever` 里，从根上杜绝。
2. **通用疑问词会把匹配带偏。**
   「怎么」「哪里」「多少钱」几乎每句都有，不过滤的话，
   「灯泡坏了找谁」会被「成绩单盖章找谁」抢走命中。它们已经在 `stopwords.txt` 里。
3. **TF-IDF 只认字面重叠。**
   「寝室灯泡坏了」和「宿舍灯坏了」，TF-IDF 算出来就是 0。
   这是它的固有瓶颈，不是 bug——语料已经足够丰富、召回率还卡在 70% 以下时，就该换语义向量方案了。
